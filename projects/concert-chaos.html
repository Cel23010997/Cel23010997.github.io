Concert Chaos

A little music, a lot of agents—and a concert that refuses to stay predictable.

Download for WindowsProject notes on GitHub

Music meets game AI

I built Concert Chaos using the supplied Rabin Engine during the Singapore Institute of Technology–DigiPen Overseas Immersion Programme. Learning game AI with Steve Rabin gave me a way to bring my love of music into a technical project: a concert whose performers, audience, spotlights and UFO each follow their own behaviour trees.

My contribution

I created the concert concept and implemented the behaviour trees and custom nodes for performer formations, crowd flocking, collision reactions, replacement audience members and concert-phase coordination. I also worked on camera panning, spotlight behaviour and audio cues. The underlying engine and supplied framework are credited to their creators.

The problem and constraint

Independent agents still need to take part in one shared performance. My project notes identify two difficult parts: keeping phase changes consistent across different behaviour trees, and synchronising audio with AI events.

I worked within an existing C++ framework. A new node needed source, header and registration changes as well as its place in a behaviour tree, so the growing number of behaviours also made organisation and debugging more demanding.

How the concert stays together

01

One shared concert state

A custom S_ConcertManager service advances phase timers and triggers audio cues. Other trees react to the shared state.

02

Four performers

Line and V-shaped formations, spins and look-up reactions turn individual agents into a coordinated routine.

03

A reactive audience

Separation, cohesion and alignment drive flocking. Collision reactions and replacement agents add interruptions to the crowd.

Debugging and iteration

The framework’s visible behaviour trees helped me follow how decisions moved between nodes. My implementation separates phase progression from individual actions: when the phase advances, the manager resets its phase timer and audio flag, while the other trees use the shared phase to select their behaviour.

The result is an existing Windows simulation with formations, crowd behaviour and concert events in one scene. I have not claimed a measured performance gain or a formal user-testing result.

Try the Windows build

Download the ZIP and extract the entire folder, then run ConcertChaos.exe. Keep all extracted folders beside it; the Source folder contains runtime behaviour-tree configuration, not C++ code. You do not need the source project or a game editor.

The simulation runs automatically. Use the Up and Down arrow keys to pan the camera; close and reopen the application to restart. This is a native 64-bit Windows build, not a browser demo.

The packaged build passed a local startup check. A complete visual playthrough has not been verified.

What I took from it

This was a chance to connect a personal interest with systems thinking. A convincing shared scene depends on small decisions working together: where an agent moves, when it reacts and which state it can trust. It sits alongside The Last Bloom, my level-design work from the same overseas learning journey.
